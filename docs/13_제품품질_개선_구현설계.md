## 1. 공통 설계 결정

### 1.1 API 호환성

1. 기존 `/api/v1/fish` 배열 응답은 FE 전환 기간 동안 유지한다.
2. cursor·facets·새 정렬 계약은 `/api/v2/fish`에 추가한다.
3. 기존 detail 응답에는 `slug`, `category`, `thumbnail`, `verificationStatus`, `ratingCount`를 additive field로 추가할 수 있다.
4. 기존 `imageUrl`, `images: string[]`는 최소 한 안정화 릴리스 동안 유지하고 FE는 신규 `media`가 없으면 legacy 필드로 fallback한다.
5. 신규 endpoint는 BE를 먼저 배포하고 FE 기능 flag를 나중에 켠다.

### 1.2 DB 변경 원칙

```text
expand → dual write → backfill → verify → enforce → read switch → contract
```

- Flyway는 forward-only로 운영하며 실패 시 down migration 대신 새 수정 migration을 만든다.
- 인덱스·제약 추가 전 운영 데이터 preflight를 실행한다.
- raw data 삭제 전 중복/대상 ID를 CSV 또는 audit table로 보존한다.
- contract migration은 구버전 애플리케이션 rollback이 필요 없다는 것이 확인된 뒤 적용한다.

### 1.3 상태·접근성 원칙

- 새 기능은 loading·empty·error·retry·dark mode·keyboard 상태까지 포함해야 완료다.
- 색상만으로 선택·검증·차트 계열을 구분하지 않는다.
- 의미 있는 텍스트는 12px 미만으로 내리지 않는다.
- 일반 텍스트 대비는 4.5:1 이상, UI 경계·큰 글자는 3:1 이상을 만족한다.
- 입력·textarea·select는 모바일 computed font-size 16px 이상으로 iOS 자동 확대를 막는다.
- 모든 주요 조작의 hit area는 최소 44×44px다.

### 1.4 데이터·트랜잭션 원칙

- API read model은 엔티티 그래프보다 DTO projection을 우선한다.
- 중복 방지는 `exists → insert`가 아니라 UNIQUE + `ON CONFLICT`로 처리한다.
- 외부 HTTP 호출·Cloudinary 처리·응답용 무거운 집계는 DB 트랜잭션 밖에서 실행한다.
- 캐시 무효화·Telegram reply는 DB commit 이후 실행한다.
- 캐시는 source of truth가 아니며 장애 시 공개 조회는 DB로 fail-open한다.

## S1 — XFF·레이트리밋·이미지 업로드·외부 HTTP 보안

**우선순위**: P0

**변경 파일**: `RateLimitFilter.java`, `ReviewController.java`, `SecurityConfig.java`, `ImageController.java`, `ImageService.java`, `TelegramBotClient.java`, `AuthService.java`, `KakaoLoginRequest.java`, `application.properties`, 인프라 설정.

### Trusted client IP

- controller/filter에서 임의의 첫 `X-Forwarded-For` 값을 직접 읽지 않는다.
- Render/Cloudflare가 외부 XFF를 제거하고 새 값을 구성하는지 staging에서 확인한다.
- framework native forwarding 또는 trusted proxy 목록 기반 resolver 하나로 통일한다.
- 조작 XFF를 바꿔도 동일 실제 client bucket을 사용해야 한다.

### Rate limit

- current `ConcurrentHashMap`의 무제한 cardinality와 O(n) purge를 제거한다.
- 단일 인스턴스 단계에서는 Caffeine bounded TTL cache, 다중 인스턴스 전환 시 Redis/Bucket4j를 사용한다.
- key는 endpoint bucket + authenticated user ID 또는 trusted client IP다.
- IP별 limiter와 별도로 global limiter를 둔다.
- 429에 `Retry-After`, reset 시각, 안정적인 error code를 반환한다.

### 이미지 업로드

단기:

- image magic bytes·5MB 제한을 Cloudinary 호출 전에 검증한다.
- 이미지 dimension·pixel count 상한을 둔다.
- global + IP/user limiter를 적용한다.
- Cloudinary `public_id`, uploader key, status, 만료시각을 저장한다.

장기 flow:

```text
POST /images/intents → signed upload → review에 assetId 첨부
→ ATTACHED 전환 → 만료 PENDING asset cleanup
```

### 외부 HTTP

- Telegram connect 2초/read 3초 timeout을 설정한다.
- bot token을 포함할 수 있는 exception message·URI를 로그에 남기지 않는다.
- Telegram reply는 `AFTER_COMMIT` 비동기로 보내며 실패해도 import를 rollback하지 않는다.
- Kakao HTTP 호출은 DB transaction 밖에서 실행한다.
- OAuth `redirectUri`는 정규식이 아니라 서버 allowlist exact match다.

**프롬프트**:
> XFF 직접 파싱을 trusted proxy-aware resolver로 교체하고 bounded TTL limiter + global limiter + 429 Retry-After를 구현해줘. 이미지 업로드는 Cloudinary 호출 전 bytes·dimension·pixel count를 검증하고 asset publicId/status를 추적하게 확장해. Telegram/Kakao 외부 HTTP는 timeout·민감 로그 제거·transaction 분리·after-commit reply를 적용해.

- [x] actor cache maximum 10,000 + TTL/global limit으로 cardinality bounded
- [x] bytes/dimension/pixel 검증 실패 이미지는 Cloudinary 호출 전 거부

### Helpful

`exists → insert → update`를 제거하고 PostgreSQL CTE 1문장으로 처리한다.

```sql
WITH ins AS (
  INSERT INTO review_helpful_vote(review_id, voter_key)
  SELECT id, :voterKey FROM review WHERE id = :reviewId
  ON CONFLICT DO NOTHING
  RETURNING review_id
),
upd AS (
  UPDATE review
  SET helpful_count = helpful_count + 1
  WHERE id IN (SELECT review_id FROM ins)
  RETURNING helpful_count
)
SELECT helpful_count FROM upd
UNION ALL
SELECT helpful_count FROM review
WHERE id = :reviewId AND NOT EXISTS (SELECT 1 FROM upd)
LIMIT 1;
```

## B3 — 시세 import bulk·dedup·가격 projection

**우선순위**: P1

**변경 파일**: `TelegramPriceImportService.java`, `ShopPriceObservationRepository.java`, `ShopPriceObservation.java`, `FishPriceQueryService.java`, price DTO, Flyway migration.

### Import flow

```text
Telegram JSON 검증·parse (transaction 밖)
→ canonical fish name 일괄 조회 1회
→ 최대 200행 JDBC batch/multi-values INSERT 1회
→ commit
→ price cache evict + Telegram reply AFTER_COMMIT
```

- `GenerationType.IDENTITY` + JPA `saveAll`에 의존하지 않는다.
- PostgreSQL JDBC `reWriteBatchedInserts=true` 또는 native multi-values를 사용한다.
- 한 webhook batch는 원자적이며 DB 오류는 신규 행 전체 rollback이다.
- `ON CONFLICT DO NOTHING`으로 확인된 중복은 오류가 아니다.

### Dedup expand/contract

기존 UNIQUE는 nullable `source_name`과 긴 `raw_text` 문제를 가진다. `dedup_hash VARCHAR(64)`를 nullable로 추가하고 애플리케이션 공통 `DedupKeyFactory`로 SHA-256을 dual-write한다.

1. nullable column 추가
2. 신규 row dual-write
3. 기존 row backfill
4. NULL·duplicate 0 검증, duplicate audit 보존
5. unique index + NOT NULL
6. bulk `ON CONFLICT (dedup_hash)` 전환
7. 안정화 후 legacy constraint·existsDuplicate 제거

### 가격 read model

전체 entity와 `rawText`를 읽지 않는 projection을 사용한다.

```java
public interface PriceRow {
    OffsetDateTime getObservedAt();
    int getPriceMinKrw();
    int getPriceMaxKrw();
    String getUnit();
    String getOrigin();
    String getSizeGrade();
    String getSourceName();
    String getCondition();
}
```

API 확장:

```http
GET /api/v1/fish/{id}/prices?days=30&resolution=DAY&maxPoints=30&variantKey=...
```

응답에 `asOf`, `currency`, `normalizedUnit`, `sourceCount`, no-data reason을 추가한다. 데이터가 커지면 일별 aggregation을 SQL로 이동한다.

**프롬프트**:
> 시세 parser와 DB transaction을 분리하고 canonical fish를 한 번에 조회해 JDBC bulk insert로 저장해. SHA-256 dedup hash를 expand/dual-write/backfill/enforce/contract 순서로 도입하고 기존 duplicate는 audit 후 처리해. 가격 조회는 rawText 없는 projection과 최대 point/resolution 계약으로 바꾸고 4 SQL을 2 이하로 줄여.

V10의 공개 seed 26종은 모두 slug가 있지만 rolling writer 호환을 위해 `fish.slug` 컬럼 자체는
nullable이다. unique name/slug, alias normalization과 trigram index는 적용돼 있다. 향후 전 writer가
slug를 보장할 때 별도 migration으로 `SET NOT NULL`을 검토한다.

### V15 expand

- `dedup_hash VARCHAR(64)`는 먼저 nullable로 추가한다.
- 애플리케이션 `DedupKeyFactory`와 V15 compatibility trigger가 byte-for-byte 같은 v1 SHA-256을 쓴다.
- trigger는 구 버전 writer가 hash를 모를 때도 값을 채워 V16 이후 rollback binary가 write할 수 있게 한다.
- 이 단계에서 legacy `uq_shop_price_observation`은 유지한다.

### V16 backfill/enforce + V17 CHECK

- V16은 기존 NULL hash를 backfill한다.
- 같은 hash 중 최소 ID를 남기고 삭제 대상 전체 JSON snapshot을
  `shop_price_observation_duplicate_audit`에 보존한다.
- NULL/duplicate 0을 검증한 뒤 hash `NOT NULL`, 64자 lowercase hex CHECK, unique index를 적용한다.
- V17은 기존 row preflight 후 `price_min/max > 0`, `min <= max`, `confidence BETWEEN 0 AND 1`을
  `NOT VALID`로 추가하고 같은 migration에서 validate한다.

### 안정화와 V18 contract

```text
SPRING_FLYWAY_TARGET=17
```

V16/V17까지 적용하는 안정화 릴리스는 위 target을 명시한다. 이 기간에 duplicate audit, hash parity,
bulk/legacy flag 전환, 오류율·readiness, 구 앱 rollback 가능성을 확인한다. 최소 한 안정화 릴리스와
운영 승인 뒤 target 제한을 제거해 V18을 적용한다. V18은 hash unique index와 NULL 0을 다시
preflight한 뒤 긴 `raw_text`를 btree key로 잡던 legacy constraint만 제거한다.

이미 적용된 V8~V18 파일을 수정하거나 down migration을 만들지 않는다. 문제는 실제 feature flag,
호환 애플리케이션 rollback, 신규 forward-fix migration으로 처리한다. 운영 snapshot dry-run,
백업·복구와 contract 승인 절차는 [`OPERATIONS.md`](OPERATIONS.md)를 따른다.

### Feature flags

실제 property/환경변수:

```properties
app.read-model.review-stat.enabled=${REVIEW_STAT_READ_MODEL_ENABLED:true}
app.catalog.v2.enabled=${CATALOG_V2_ENABLED:true}
app.price-import.bulk.enabled=${PRICE_IMPORT_BULK_ENABLED:true}

```

FE 전환 flag는 `VITE_CATALOG_V2_ENABLED`, `VITE_REVIEW_V2_ENABLED`이다. 둘 다 기본 true이며,
false이면 v1만 사용한다. true인 상태에서도 v2의 네트워크 오류·404·5xx·503 또는 비정상 payload는
bounded v1 요청으로 fallback한다.

위 기본값은 모두 true다. 신규 환경의 점진 배포에서는 **코드 배포 전에 환경변수를 false로
명시**하고 한 개씩 켠다. catalog/source flag OFF는 503 `FEATURE_DISABLED`, review stat OFF는 live
aggregate, bulk OFF는 webhook당 최대 50행의 legacy persist 경로, public cache OFF는 NoOp cache+HTTP no-store다.

### Rollback

- FE는 신규 media/source/slug가 없으면 legacy 필드와 ID URL을 사용한다.
- `/api/v2` 장애 시 `/api/v1`로 즉시 전환한다.
- review stat flag OFF 시 live aggregate fallback한다.
- bulk import flag OFF 시 legacy importer를 제한적으로 재활성화하되 webhook row limit을 둔다.
- cache 장애는 공개 read에서 DB fallback한다.
- cache eviction·Telegram reply 실패는 이미 commit된 transaction을 rollback하지 않는다.
- stat dual-write 실패는 review mutation 전체를 rollback한다.
- Cloudinary 성공 후 review 실패는 asset을 PENDING으로 남기고 TTL cleanup한다.
- Flyway는 rollback하지 않고 forward fix하며 contract 전에는 구 column/constraint를 유지한다.
- V18 contract 뒤에는 legacy raw-text constraint가 있다고 가정하는 구 앱을 재배포하지 않는다.

### 배포 전 운영 확인

- DB backup 또는 snapshot 생성
- Render/Neon 동일 리전 확인
- migration 예상 lock·시간 확인
- Vercel preview에서 rewrite·prerender·Insights 확인
- Cloudinary quota·orphan cleanup 확인
- 기존 익명 후기·회원 후기·북마크 병합 회귀 확인

명령·승인·증적 형식은 [`OPERATIONS.md`](OPERATIONS.md)를 따른다. 스크립트와 런북이 존재하는 것은
실제 운영 백업·restore drill·staging 배포가 완료됐다는 뜻이 아니다.
